# 公司筆錄角色與問句規則

## 1. 已確認需求

- 公司提供的每一份筆錄均有明確對應角色。
- 公司筆錄中的問句屬於該筆錄對應角色，不視為角色錯置問題。
- 系統不得因自行推測問句口吻而擅自改派角色、刪除或改寫公司問句。

## 2. 角色來源

公司原始筆錄或公司核准清冊是角色對應的權威來源。至少包括：

- 通用被害人筆錄 → 被害人。
- 通用涉嫌人筆錄 → 涉嫌人。
- 通用涉嫌人筆錄（移送） → 無被害人案件的移送涉嫌人。
- 家庭暴力、違反保護令、跟蹤騷擾、性騷擾、兒少性剝削、性侵害及性影像等專用筆錄 → 依各原始範本指定角色。

## 3. 公司原始問句

- 公司問句應保存原文、原順序、來源檔案、來源位置及檔案 SHA-256。
- 公司原始問句不得由 AI 自動改寫、合併、拆分或刪除。
- 需要加入說明或中性補問時，應新增獨立題目，不得改動公司原文。
- 新增題目必須標明來源為系統補問，不得偽裝成公司原始題目。

## 4. 題目合併順序

單一角色的筆錄依下列順序組成：

1. 該角色適用的法定程序及權利告知。
2. 該角色的公司通用筆錄問句。
3. 該案件適用的公司專用筆錄問句。
4. 公司新套表中對應角色及罪章的問句。
5. 公司問句未涵蓋的核心、區分及補強問句。

系統補問題仍須遵守：

- 禁止引導。
- 使用一般人可以理解的文字。
- 一題處理一個主要事實。
- 候選罪章不得表述為犯罪成立。

## 5. 角色完整性檢查

- 系統只檢查「所選範本是否與公司指定角色一致」。
- 系統不得僅因文字中出現「你」、「對方」、「被害人」或「涉嫌人」等稱謂，就自行判定公司題目角色錯誤。
- 若設定檔把某份公司範本連到不同角色，應視為設定完整性錯誤並停止輸出。
- 專用範本尚未完成逐題載入、順序核對及輸出驗證時，對應路由應 fail closed。

## 6. 新增或更新公司範本

新增或更新範本時，應依序完成：

1. 登錄範本名稱、角色、版本、適用條件及來源 hash。
2. 唯讀解析全部問句及原順序。
3. 與既有通用題及罪章題進行 exact／semantic 去重檢查。
4. 建立角色、路由及啟用條件對照。
5. 執行逐題輸出與八頁限制測試。
6. 經公司指定人員核准後發布新版本。

舊案件應繼續保存並使用當時已核准的範本版本，不得被新版範本自動回寫。

## 7. 驗收條件

- 每份公司筆錄只會進入其公司指定角色流程。
- 公司問句的文字及順序可與登錄來源逐題核對。
- AI 或系統補問題與公司原始題目具有不同來源標記。
- 尚未完成整合驗證的專用範本不能產生正式筆錄。
