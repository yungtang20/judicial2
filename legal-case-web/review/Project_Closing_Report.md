# 法律混淆組合與底層事實問句庫 — 專案最終結案報告
**生成日期:** 2026-10-15  
**專案狀態:** `PASS` (Phase 1 至 Phase 6 核心建置與優化圓滿完成)  
**執行模式:** 雲端 AI 法律邏輯推演 + 本地 AI 防卡死檢索 + 嚴格獨立審查  

## 1. 專案目標與達成率
本專案旨在建立一套「高準確度、無斷鏈、符合第一線執法實務」的法律混淆組合問句庫，成果如下：
- **索引淨化與擴充**：從初始清單中成功剔除「純身分加重 / 法條競合」等偽混淆，並擴充至 **50 組 PAIR**，完整涵蓋刑法分則核心爭議、刑行界分（社維法）、聚眾與槍砲等高頻執法痛點。
- **問句品質革命性躍升**：透過 Task 5 自動化 QA 與人工覆核，成功將所有殘留「法條轉寫」的問句，100% 重構為符合《警察偵查犯罪手冊》第 120/127 條的「底層事實提取」白話問句。
- **案例實證覆蓋**：累計成功檢索並驗證 **50+ 筆** 真實裁判案例（涵蓋最高法院至地方法院），確保每一組區辨邏輯均有實務見解支撐，且嚴格遵守「失敗即跳過、絕對不捏造」的最高原則。
- **手冊級問句補齊**：針對無複雜混淆的「身分/結果確認型」PAIR（如妨害公務、酒駕、家暴、少年事件），獨立生成符合通用筆錄模板的客觀事實確認問句，實現無死角覆蓋。

## 2. 核心產出檔案清單 (最終交付版)
為確保系統載入效率與維護性，`review/` 目錄現僅保留以下核心檔案：
1. `A_confusion_pairs_v4.yaml`：**最終正規化索引** (50 組 PAIR，含刑行界分與 UNRESOLVED 標記)。
2. `B_master_case_studies.yaml`：**最終案例與問句資料庫** (經 QA 修正與深度淬鍊，含 50+ 筆真實案例紀錄與底層事實問句)。
3. `B_single_offense_questions.yaml`：**單一罪名核心事實問句** (無混淆爭點，專用於固定客觀構成事實)。
4. `C_deep_validation_report.md`：高價值盲點 (PAIR-047/048/052) 的多輪交叉驗證與問句淬鍊報告。
5. `extracted_excel_questions.md`：從實務套表提取之基準問句庫 (Ground Truth)。
6. `00_6_local_env_diagnosis.md`：本地執行環境診斷與防卡死策略紀錄。

## 3. 問句優化成果示範 (Before vs After)
| 混淆組合 | ❌ 錯誤示範 (法條轉寫) | ✅ 正確示範 (底層事實提取 / 手冊級) |
|---|---|---|
| **竊盜 vs 使用竊盜** | 你在未取得所有者同意前，是否 knowingly 无 lawful permission 却仍 decide 取得使用？ | 你把這台機車騎走之前，有沒有先問過車主能不能借用？當時車主人在哪裡？ |
| **殺人 vs 過失致死** | 你對撞擊後車輛可能失控、偏行撞擊他人是否有具體預見？ | 撞上去之前，你有沒有踩煞車、按喇叭或轉方向盤閃避？如果沒有，是來不及還是不想閃？ |
| **妨害公務 vs 傷害** | 對方當時是否正在依法執行職務？ | 事發當時，對方穿著制服或配戴識別證嗎？你怎麼知道他是在上班？ |
| **少年觸法 vs 虞犯** | 行為是否已該當刑罰法律客觀構成要件，抑或僅屬曝險未觸法之虞犯事由？ | 行為人做的這件事，是單純的翹課、半夜在外遊蕩，還是有具體動手打人、偷東西或破壞東西的行為？ |

## 4. Phase 2 & 3 高價值盲點補齊成果
在檢視清單後，專案額外補齊了實務上極度缺漏的真爭點，並已成功檢索案例：
- **幫助詐欺 vs 詐欺共犯**：聚焦「知情程度＋參與深度」（如：是否知悉款項為詐騙贓款、有無收購指揮提款等分工）。
- **洗錢 vs 前置犯罪**：聚焦「獨立洗錢意思」（如：透明匯款無斷點 vs 現金人頭多層轉帳）。
- **竊占 vs 竊盜**：聚焦「客體與行為態樣」（如：越界鋪設水泥占用不動產 vs 搬走動產）。
- **正當防衛/緊急避難**：聚焦「侵害是否仍在持續」與「有無他法＋最小損害」的具體動作事實。

## 5. 後續維護與系統整合建議 (Next Steps)
### A. 系統整合 (LLM Application)
- **RAG (檢索增強生成)**：可將 `B_master_case_studies.yaml` 作為向量資料庫的 Chunk。當使用者輸入案件事實時，系統可檢索最相關的 PAIR，並直接調用其中的 `neutral_questions` 引導使用者補充事實。
- **Few-Shot Prompting**：可將 `C_deep_validation_report.md` 與 `extracted_excel_questions.md` 中的 Before/After 範例作為 System Prompt，強制約束未來 LLM 生成問句時必須遵守「底層事實提取」原則。

### B. 未來新增 PAIR 的標準作業程序 (SOP)
1. **定義真爭點**：確認新 PAIR 是否為「保護法益重疊、行為外觀相似」，若非，則標記為 `UNRESOLVED` 或轉為「身分/結果確認型」。
2. **防卡死檢索**：使用 `taiwan-legal-db`，搭配 `reasoning_keyword` 抓取 ≤800 字的核心區辨段落。
3. **問句生成**：嚴格套用「時間、地點、人物、具體動作/對話、物品狀態」五要素，禁止任何法條術語，並允許「記不清楚」的回答。
4. **獨立審查**：執行自動化 QA 腳本，檢查問號、長度與禁止詞彙。
