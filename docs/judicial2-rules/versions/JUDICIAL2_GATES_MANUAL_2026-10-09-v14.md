## 1. 目的與範圍

本手冊定義案情輸入至 Gate 3 的關卡規則，並規定案件路由。流程終點為 Gate 3，最終程序判斷、移送書、起訴書與文書由使用者自行處理。

每個 Gate 檢查輸入合格、處理合法、輸出合格。違規時只有兩種處理：補充後進入、強行通過。

---

## 2. 核心設計原則

1. 每個 Gate 至少一次 LLM 呼叫，每個子規則的處理與檢查在同一次呼叫完成。
2. 每個 Gate 只做一件事，職責不重疊。Gate 1 負責事實與基本要件的標示；Gate 2 與 Gate 3 不得重新判斷 Gate 1 已標示之要件。
3. 處理結果只有兩種：補充後進入、強行通過。
4. 不推論、不合併、不跳步。
5. warning 全程傳遞，不得消除。
6. 角色分流：被害人端只處理時、地、物、人、事；涉嫌人端另處理刑法第 21～31 條與第 57 條；證人端只提供事件過程內容。
7. 以「行為」為單位建立單元。同一人可同時為被害人與涉嫌人，各自產出筆錄。
8. 告訴乃論以條文明文規定為準；條文未明文者視為非告訴乃論，並標示依據。報告用語（如「提告」「告訴」）不作為判斷依據。
9. 受理性質為「備案」者，不進入刑事流程，無論內容為何。
10. Gate 2 只給案類與法條候選，不確定罪章。主觀問題不在 Gate 2 處理。
11. Gate 3 涉嫌人問句以德日三階層為內部框架，三段論表達，因果論放入構成要件該當性之客觀要件。內部對應表不給涉嫌人看。
12. Gate 3 不判定刑責，只生成問句，不作追訴權或告訴期間之判斷。
13. 涉嫌人問句白話、不引導、不浪費紙張，不以是非題留大片空白。
14. 單一來源原則：每個事實單元只在 Gate 1 產生一次。Gate 2、Gate 3 只引用 unit_id。
15. 規則與案例分離：規則正文不含具體案件事實。測試紀錄與模擬案例另檔管理，不具規則效力。
16. Gate 凍結：進入下一 Gate 後，前 Gate 輸出不得回頭修改。

## 3. 共通規則

**C-R01：同次輸出檢查**
每個 Gate 的處理結果與規則檢查須在同一次 LLM 呼叫完成。不得先輸出結果，再另外呼叫檢查。

**C-R02：處理結果只有兩種**
合格則直接進入下一 Gate。不合格則補充後進入，或強行通過。不得有第三種結果。

**C-R03：warning 全程傳遞與編號**
1. 每個 Gate 產生的 warning 須傳入下一個 Gate。下一個 Gate 不得消除、不得改寫，只能新增。
2. 每個 warning 加 source_gate，並依「Gate 代號-流水號」編號，例如 G1-W01、G2-W03。
3. 同一問題在不同 Gate 出現時，承接原 warning 編號，不另立新編號。

**C-R04：不推論、不合併、不跳步**
不得推論未明示的內容。不得合併不同事件、不同人物。不得跳過任何 Gate，除非依路由規則。

**C-R05：UNKNOWN 保留**
UNKNOWN 代表資料不足，不得強制轉為 TRUE、FALSE、該當或不該當。NOT_APPLICABLE 代表不適用，與 UNKNOWN 不同。

**C-R06：角色分流**
被害人端：只處理時、地、物、人、事，不處理主觀。
涉嫌人端：處理人、事、時、地、物，加上刑法第 21～31 條與第 57 條。
證人端：只提供事件過程內容，加強證據。

**C-R07：單一來源原則**
每個事實單元只在 Gate 1 產生一次。Gate 2、Gate 3 只引用 unit_id。若須引用內容，只引用欄位，不複製全文。

**C-R08：角色設定**
本系統執行者設定為法律專家。所有判斷以中華民國（臺灣）法律為基準。所有輸出須區分：事實、法律候選、內部對應、不確定事項。

**C-R09：STE100 規則**
本系統遵守 STE100：
1. Simple：輸出簡明，不混雜無關判斷。
2. Transparent：每個判斷標示依據。
3. Evidence-based：以輸入事實與 source_raw 為限。
4. 100% traceable：可回溯 unit_id、source_gate、warning。
若使用者提供正式 STE100 定義，從其定義。

**C-R10：案件獨立原則**
每次案件都是新案件。不得沿用前案事實、人物、warning、法條候選或問句。除使用者明示同一案件外，一律從 Gate 1 重新開始。

**C-R11：Gate 凍結與不可回溯**
1. Gate 輸出經檢查合格並進入下一 Gate 後，即凍結。
2. 後續 Gate 不得回頭修改前 Gate 的事實單元、案類候選、法條候選、問句或 warnings 原文。
3. 發現前 Gate 缺漏或錯誤時，只能在當前 Gate 新增 warning。
4. 若補充涉及前 Gate 事實，應終止流程，從 Gate 1 重新開始。
5. 每個版本須有 version_id、parent_version_id。

**C-R12：補充的範圍**
1. 補充僅能在當前 Gate 內進行，不得跨 Gate 回溯。
2. 前 Gate 不合格，應在該 Gate 內補充後再進入下一 Gate。
3. 進入下一 Gate 後才發現前 Gate 缺漏，不得回頭補，只能：當前 Gate 以 UNRESOLVED 或 warning 強行通過；或終止流程，從 Gate 1 重跑新版本。

**C-R13：版本控制**
同一案件每次重跑視為新版本，格式為 v1、v2、v3。新版本須從 Gate 1 重新開始，不得將新版本事實回寫舊版本。舊版本保留供追溯。

**C-R14：規則與案例分離**
1. 規則條文不得包含具體案件事實、人物、地點、時間、罪名候選或問句。
2. 模擬案例與測試紀錄僅供說明，不得寫入規則本體，不得作為其他案件之判斷依據。
3. 規則與案例應分檔、分節、分版本。

**C-R15：日期與年次正規化**
1. 來源日期格式多樣（如「1214/0306」「114年01月17日」「0117/1828」「115年10月03日」）。統一輸出為「民國年／月／日 時分」，原文保留於 source_raw。
2. 年份缺漏時，以報告日期之年份推定，並標示「推定」，加 warning。
3. 年份與報告日期明顯不符，不自行修正，保留原文，加 warning，請承辦人確認。
4. 年次以民國年次記錄，不自行換算西元。年齡推算須標示「推算」。

**C-R16：人別比對**
1. 同一人在不同紀錄中之寫法（姓名部分遮蔽、代稱、僅有年次、代號、外文姓名）須以比對依據記錄。
2. 比對依據包括：姓名、年次、車號、案號、證件號碼之部分資訊、聯絡方式等。外文姓名無年次者，以證件資訊之部分比對，不足時標 UNKNOWN。
3. 同一紀錄內或跨紀錄之姓名近似（字形或字音相近但不同字，如「菜」與「蔡」）不得自行合併，須加 warning「姓名近似，待比對」。
4. 依據不足時標 UNKNOWN，不得自行合併。比對結果記錄於 Gate 1，後續 Gate 不得變更。
5. 比對無法確認者，保留為獨立單元，加 warning「人別待比對」。

**C-R17：個資最小化**
1. 身分證字號、電話、護照號碼、住址詳細資料、車號等，於條陳與問句輸出中僅保留必要部分，不得全文帶入。
2. 條陳受理之案由、時地、物、人、事可保留必要識別；問句不得出現可直接識別之證件號碼或電話。
3. 內部 source_raw 保留原文供追溯，但不得輸出至條陳或問句。

**C-R18：同一事件之報告版本**
1. 同一事件可能有初報、續報、結報、更正等多份報告。
2. 每份報告記錄「報告階段」欄位。
3. 以結報為準，前版保留供追溯。
4. 同一事件的多份報告內容互相矛盾（如行駛方向、受損部位、時間），不得合併、不得自行採用其一，加 warning「報告內容矛盾，待比對」，並各自保留事實單元。
5. 不同事件之判斷依時、地、人、物綜合比對，不得僅因案由相同即視為同一事件。

**C-R19：同一事件之重複報告**
同一時、地、車號或人別之報告，若內容高度重疊但報告人不同，標示「可能重複，待比對」，加 warning，不自行刪除任一份。

**C-R20：時序一致性檢核（新增）**
1. 每件報告須檢核時序：發生時間 ≤ 報案時間 ≤ 破獲或查獲時間（或受理時間）。
2. 違反者不自行修正，保留原文，加 warning「時序不一致，待確認」。
3. 同一事件之多個時間點（如交付時間與發現時間）須分開記錄，不得以單一時間取代。

**C-R21：案號格式檢核（新增）**
1. 案號依常見格式檢核（如 Z 字開頭之 e 化案號、165 案號、婦幼案號、證明單號、通報案號等），格式不符者保留原文，加 warning「案號格式待確認」。
2. 案號格式清單須另檔維護，不列於本手冊正文，並隨實務更新。

**C-R22：法條資料表（新增）**
1. 本系統引用之所有法條，須載入法條資料表，欄位如下：條次、條文原文、最重本刑、告訴乃論依據、追訴期間、來源（條文或判決書）、查證日期、狀態。
2. 狀態值域為「已確認」（有條文原文）、「二手來源」（僅有第二手資料，須補查原文）、「待查」（尚未取得）。
3. 規則中引用之條文，若狀態非「已確認」，須於該規則標示，不得作為確定依據。
4. 法條資料表擴充，須依本手冊第 11 節之程序進行。

## 4. Gate 總覽與路由

| Gate | 名稱 | 輸入 | 輸出 | 呼叫 |
|---|---|---|---|---|
| Gate 1 | 事實單元、路由、基本要件與追訴權標示 | 原始案情 | 路由結果、被害單元、行為單元、證人陳述、程序與其他要件事實、追訴權狀態 | 1 次以上 |
| Gate 2 | 被害人端案類、法條與問句 | Gate 1 被害單元、程序事實（僅路由 A） | 案類候選、法條候選、告訴乃論、告訴期間判斷、被害人筆錄問句、被害人程序問句、受理條陳 | 1 次以上 |
| Gate 3 | 涉嫌人筆錄問句生成 | Gate 1 行為單元（主輸入）、被害單元（比對）、程序事實、罪章與法條來源（路由 A 為 Gate 2，路由 B 為 Gate 1）、Gate 1 之追訴權狀態 | 涉嫌人白話問句、涉嫌人程序問句、內部對應表 | 1 次以上 |

### 4.1 被害人與無被害人之定義（新增）

1. **被害人**：直接受侵害之自然人或法人（包括店家、公司、機關之特定人員）。
2. **無被害人**：無可特定之直接受侵害人，保護法益為社會法益或國家法益。
3. 公務員執行職務遭妨害（如妨害公務），有可特定之執行人員者，該執行人員為被害人，歸路由 A。無可特定之執行人員者，歸路由 B。
4. 公務文書或公信力受侵害（如偽造文書、使公務員登載不實），無可特定之直接受侵害人者，歸路由 B。若有特定當事人因此受損，該當事人為被害人，歸路由 A，並於 Gate 1 加 warning「被害人認定待確認」。
5. 被害人身分未確定者，依 G1-R10 處理，不因此歸入路由 B。

### 4.2 受理性質（修正）

受理性質值域：受理、告訴、告發、報案、備案、通報、申訴、函送、移送、查獲、其他。

| 受理性質 | 性質說明 | 路由影響 |
|---|---|---|
| 受理 | 依規定受理之刑事案件 | 可歸 A 或 B |
| 告訴 | 被害人或告訴權人之告訴 | 可歸 A 或 B |
| 告發 | 公務員或他人依職務或義務之告發 | 刑事內容可歸 A 或 B，告發人不視為被害人 |
| 查獲 | 警方現行犯或通緝等之查獲 | 可歸 B |
| 報案、通報、申訴、函送、移送 | 依其性質另行記錄 | 不作為告訴；刑事內容依 4.3 第 2 點辦理 |
| 備案 | 登記備查 | 排除於刑事流程（見 4.3 第 1 點） |

性騷擾申訴依性騷擾防治法，屬申訴，不屬告訴。

### 4.3 路由規則

| 路由 | 條件 | 後續流程 | 典型案件 |
|---|---|---|---|
| A | 有被害人（依 4.1），刑事案由，受理性質為受理、告訴或告發 | Gate 1 → Gate 2 → Gate 3 | 詐欺、竊盜、傷害、妨害性隱私、業務侵占、已受理之妨害公務 |
| B | 無被害人（依 4.1），刑事案由，受理性質為受理、告發或查獲 | Gate 1 → Gate 3（不經 Gate 2） | 通緝查獲、酒駕、毒駕、毒品（線上立破）、公共危險、無特定受害人之偽造文書告發 |
| C | 有案號，非刑事（或備案），或民事用途 | Gate 1 → 非罪受理紀錄 | 失蹤人口撤尋、非道路車禍報案證明、遺失物備案、車損備案、信用卡盜刷備案 |
| D | 無案號，且非刑事案由（或備案），非行政裁處 | 不進入流程，保留路由結果與 source_raw | 災害、死亡相驗、救護、糾紛、為民服務 |
| E | 行政裁處案件（社會秩序維護法、道路交通管理處罰條例等） | Gate 1 → 移送裁罰紀錄（不進入 Gate 2、Gate 3） | 社維法違序、自行車酒駕行政裁罰 |

路由判斷規則：
1. **備案排除**：受理性質為備案者，不進入路由 A 或 B。有案號者歸 C，無案號者歸 D。若內容屬刑事行為，於路由結果記錄「備案之刑事內容，未進入刑事流程」，加 warning「內容疑似刑事，承辦人如需追訴應另行受理」，由承辦人判斷。
2. **刑事內容之非告訴性質**：報案、通報、申訴、函送、移送之刑事內容，不因受理性質而排除於刑事流程之外，但不作為告訴；若無受理或告訴，依 4.3 第 1 點之原則，記錄提示，不產出刑事單元。
3. **案號缺漏**：受理性質為受理、告訴或告發，且案由為刑事案由者，不得歸 D。案號標 UNKNOWN，加 warning「案號未填，請承辦人補填」，依案由路由為 A 或 B。
4. 同一事件同時有刑事與行政部分者，分別路由，各自記錄。
5. 路由 B 之罪章與法條由 Gate 1 標示（見 G1-R14）。通緝書內容未附者罪章候選標 UNKNOWN。
6. 路由 B 之告訴乃論、告訴期間、被害人問句標示 NOT_APPLICABLE。追訴權狀態仍由 Gate 1 標示（見 G1-R15）。
7. 路由 C 產出非罪受理紀錄，不產出案類與涉嫌人問句。
8. 路由 E 依 G1-R16 記錄行政時效與移送事實，流程終止。

| 強行通過 | 發現問題但不影響核心結論，記錄 warning 後進入下一 Gate | 記錄 warning → 進入 |

## 6. Gate 1：事實單元、路由、基本要件與追訴權

### 6.1 目的
從原始案情抽出以行為為中心的事實單元，決定路由，記錄程序與其他要件事實，並依法條資料表標示追訴權狀態。被害人端不處理主觀，涉嫌人端才處理主觀。

### 6.2 被害單元要素

| 要素 | 說明 |
|---|---|
| 時 | 發生時間（正規化後）、報案時間、知悉犯人時間 |
| 地 | 發生地點，網路行為之平台或社群位置 |
| 物 | 被害客體（財產、身體、名譽、隱私、國家公權力等） |
| 被害客體類型 | 個人法益／財產法益／國家法益／社會法益 |
| 人 | 被害人（自然人或法人，見 4.1）、行為人（人別依 C-R16） |
| 報告人 | 報案人，與被害人不同時須分別記錄 |
| 事 | 案件過程 |
| 是否有證人 | 是／否／UNKNOWN |

### 6.3 行為單元要素

| 要素 | 說明 |
|---|---|
| 人 | 涉嫌人身分（人別依 C-R16） |
| 事 | 行為、手段 |
| 時 | 行為時間（正規化後） |
| 地 | 行為地點 |
| 物 | 行為客體 |
| 法條標示 | 案由或查獲內容對應之條文（路由 B 必填，見 G1-R14） |
| 刑法21～31條 | 有無阻卻違法、責任能力、共犯等，依法檢驗 |
| 刑法57條 | 犯後態度、生活狀況、品行等，科刑審酌 |
| 互毆欄位 | 先行出手、防衛情狀、反擊程度，僅涉互毆時填寫 |
| 是否有證人 | 是／否／UNKNOWN |

### 6.4 證人陳述
只提供事件過程內容，加強證據，不構成獨立要素。有證人時輸出證人陳述；無證人時標 NOT_APPLICABLE；不明時標 UNKNOWN。

### 6.5 程序與其他要件事實

### 6.7 規則清單

**G1-R01：結構完整**
1. 被害單元：時、地、物、被害客體類型、人、報告人、事、是否有證人欄位皆存在。
2. 行為單元：人、事、時、地、物、法條標示、刑法21～31、刑法57、是否有證人欄位皆存在。
3. 證人陳述：有證人時，陳述內容、加強證據欄位存在；無證人時標 NOT_APPLICABLE。
4. 程序與其他要件事實：第 6.5 節所列欄位皆存在。
5. unit_id、source_raw、warnings 欄位存在。
6. 無被害人之案件，被害單元標 NOT_APPLICABLE，不視為結構缺漏。

合格則直接進入；不合格則補充後進入。

**G1-R02：角色合法**
1. 被害單元須有被害人、行為人欄位。被害人可為自然人或法人（見 4.1）。
2. 行為單元須有涉嫌人欄位。
3. 狀態值域為 RESOLVED、UNRESOLVED、NOT_APPLICABLE。
4. UNRESOLVED 人物不得被合併。
5. 同一自然人於不同事件中可分別為被害人或行為人，依行為分開建立單元，不得在同一單元內混用角色。
6. 報告人與被害人不同時（如店長代為報案、特助代為報案），須分別記錄，不得以報告人取代被害人。

**G1-R03：描述與來源品質**
1. 行為、結果描述須為客觀事實，不得寫法律判斷。主觀欄位僅涉嫌人端處理。
2. 法律判斷詞彙：
   - 罪名詞：詐欺、恐嚇、殺人、強制、背信、偽造文書等。
   - 法律定性詞：不法所有意圖、傷害故意、詐欺故意等。
   - 責任評價詞：正當防衛、緊急避難、故意、過失等。
   - 構成要件用語：竊取、竊盜、侵占、取走等，仍列為法律判斷詞。
3. 不列入法律判斷詞：未結帳離去、拿取、帶走。
4. 陳述來源為警方研判、推測或分析者，不得列為事實，加 warning「警方研判，非客觀事實」，保留原文。
5. 每個事實單元須有 source_raw。

不合格處理：含法律判斷詞彙、陳述來源為研判者，強行通過並加 warning；source_raw 為空或被害人端有主觀欄位者，補充後進入。

**G1-R04：事實分組合法**
同一單元內的行為，須滿足至少一項：同一行為人、同一被害人、時空密接、因果相連、目的同一。不同單元之間不得有上述關聯。不合格則要求重新分組。

**G1-R05：證據來源與保全**
凡涉及物證（手機、影像、檔案、物品）或取證行為者，須記錄：物證名稱與數量、取得人、取得時間與地點、取得方式（扣押、交付、拾獲、自行取得、同意搜索等）、目前保管人、是否取得同意及同意範圍。無法確認者標 UNKNOWN，加 warning。取證程序合法性由使用者判斷，本 Gate 只記錄事實。

**G1-R06：雙重身份與筆錄單元**
1. 同一自然人同時為被害人與涉嫌人時，各自的行為分別建立單元。
2. 每一個被害單元產出一份被害人筆錄；每一個行為單元產出一份涉嫌人筆錄。
3. 份數依單元數量決定，不以人為單位。
4. 每份筆錄只包含其對應單元的內容，跨份引用只能以 unit_id 作比對，不得將對方的主觀評價寫入己方筆錄。
5. 每份筆錄各自保留 warning，並標註所屬單元與身份。
6. 雙方互告各單元獨立判斷，不因對方提告而合併或停止。

**G1-R07：互毆之客觀記錄**
凡案情顯示雙方皆有攻擊行為，行為單元須記錄：先行出手者（依證據記載，或 UNKNOWN）、防衛情狀（對方有無現在不法侵害之記載，或 UNKNOWN）、反擊程度（客觀描述）、是否有證人或影像可佐證。本規則只記錄事實，不判斷是否成立正當防衛。

**G1-R08：路由判定**
Gate 1 完成事實抽取後，依第 4.3 節判定路由。路由結果於 Gate 1 輸出，後續 Gate 不得變更。

**G1-R09：告訴期間**
1. 單一行為：自得為告訴之人知悉犯人時起算，六個月內為之（刑事訴訟法第 237 條第 1 項，已確認）。
2. 連續或繼續行為：自知悉最後一次行為或行為終了時起算（大法官釋字第 108 號，已確認）。
3. 發生時間不作為告訴期間之起算點。內部若需要「發生時間加六個月」之參考截止日，須另列欄位，標示「非法定起算點，僅供參考」。
4. 起算點不明者，標 UNKNOWN，加 warning。
5. 本 Gate 不作正式期間計算結論，由使用者確認。

**G1-R10：未確定被害人之單元**
被害人身分未確定之物品或損害，建立未確定被害單元，被害人標 UNRESOLVED，不得以推測補入。Gate 2 標示待確認，不產出被害人問句。

**G1-R11：報告版本與矛盾**
依 C-R18 與 C-R19 處理。同一事件多份報告，記錄報告階段，以結報為準，前版保留；報告內容矛盾者各自保留事實單元並加 warning。

**G1-R12：程序時限（待查）**
逮捕、解送、移送之時限須記錄於程序時限事實。法定時限之條文待查，確認前標 UNKNOWN，不得依經驗值判定是否逾時。

**G1-R13：物品處置**
扣案物或查扣物品須記錄處置方式與決定人。拋棄、廢棄、無法入庫之物品，須記錄處置依據。依據不明者標 UNKNOWN。

**G1-R14：路由 B 之罪章與法條標示**
1. 路由 B 不經 Gate 2，罪章與法條於 Gate 1 標示，依案由與查獲內容，至條次為止；已知項、款者寫到項、款。
2. 案由僅寫類別（如「公共危險」）而無法對應條次者，標 UNKNOWN，加 warning，不得由 Gate 3 自行推定。
3. 罪章來源註明為案由、查獲內容或通緝書。通緝書內容未附者，罪章候選標 UNKNOWN。
4. 條文狀態非「已確認」者，須標示其狀態（見 C-R22）。

**G1-R15：追訴權標示（修正，由 Gate 1 統一標示）**
1. 追訴權依刑法第 80 條，以最重本刑對應之期間計算，自犯罪成立之日起算；犯罪行為有繼續狀態者，自行為終了之日起算（刑法第 80 條第 2 項，已確認）。
2. 最重本刑由法條資料表取得。狀態非「已確認」者，追訴期間與追訴權狀態標 UNKNOWN，加 warning。
3. 「發現時間」與「犯罪成立日」須分別記錄，發現時間不得取代犯罪成立日。
4. 發生時間與犯罪成立日不同時（如交付時間與發現時間），以犯罪成立日為準，兩者皆須保留於事實單元。
5. 追訴權狀態由 Gate 1 標示，路由 A 與路由 B 皆適用。Gate 2 與 Gate 3 只承接，不得重新判斷。
6. 告訴期間與追訴權各自獨立判斷，任一逾期即需標示，不得以另一項之結果取代。

**G1-R16：行政裁處時效（新增）**
路由 E 之案件，須記錄違反行為成立日，並依各行政法規之時效規定標示：
1. 社會秩序維護法第 31 條：違反本法行為逾二個月者，警察機關不得訊問、處罰，並不得移送法院，期間自違反行為成立之日起算，但行為有連續或繼續狀態者，自行為終了之日起算（已確認）。
2. 道路交通管理處罰條例之時效條文：待查，確認前標 UNKNOWN，加 warning。
3. 行政時效逾期者，標示「行政時效已逾」，加 warning，不得以行政裁處作成結論。

**G1-R17：管轄與轄區外受理**
1. 犯罪地不屬本所轄區，或受理機關與管轄機關不一致者，於管轄事實標示。
2. 轄區外受理之案件，仍依路由建立事實單元，保留供追溯。
3. 轄區外案件不得以本所名義產出條陳，標示「建議移送」，加 warning，由受理人員決定移送。
4. 受理與管轄不一致不影響路由判斷，但須於 Gate 2、Gate 3 之 warning 中承接。

**G1-R18：路由 C、D 之刑事內容提示**
備案或其他非刑事路由中，內容屬刑事行為者，僅記錄提示，不產出任何刑事單元，不進入 Gate 2、Gate 3。

### 7.4 規則清單

**G2-R01：案類候選**
1. 每個被害單元須給出案類候選。
2. 案類候選須有事實基礎，理由欄須引用事實。
3. 無事實基礎者不得列。
4. 若無案類，標 UNKNOWN，補充後進入。

**G2-R02：法條候選**
1. 每個案類至少對應一個法條，法條須於法條資料表中有紀錄。
2. 法條至少寫到條；已知項、款者寫到項、款。
3. 法條與案類須相符。
4. 法條狀態非「已確認」者，須標示其狀態。

**G2-R03：告訴乃論判準**
1. 告訴乃論以條文明文規定為準。明文規定為告訴乃論者標「是」；條文未明文者標「否」，並註明條文依據。
2. 關係影響告訴乃論者，依該條文判斷，關係不明時標「視關係而定」。
3. 報告用語（「提告」「告訴」「撤回」）不作為判斷依據。
4. 公務員執行職務時犯刑法第 277 條第 1 項傷害罪者，依第 287 條但書為非告訴乃論。行為人是否為公務員執行職務不明者，標 UNKNOWN。
5. 被害人為公務員、保護法益為國家法益者，依條文判斷，條文未明文者標「否」。
6. 條文原文未確認者標「待查」，加 warning，不得作為告訴乃論之確定依據。

**G2-R04：warning 繼承**
Gate 1 warnings 須完整傳入 Gate 2，保留原文，不得消除或改寫，只能新增，並加 source_gate。

**G2-R05：被害人筆錄問句生成**
1. 每個候選罪章至少一組，有幾個候選罪章就產出幾組。
2. 每組至少含三欄：候選罪章、核心問句、判定缺少的補充問句。其餘欄位得依案情增列。
3. 問句限被害人端客觀事實，不問行為人主觀，不作法律判斷。
4. 無缺少時，「判定缺少的補充問句」寫「無」或「目前無缺少」。
5. 問句不得出現可直接識別之證件號碼或電話（依 C-R17）。

**G2-R06：被害人程序問句生成**
1. 管轄、告訴期間、告訴乃論、程序要件、其他法律要件，每項至少一組。
2. 問句限被害人端客觀事實，不問主觀，不作法律判斷。
3. 無缺少時寫「無」或「目前無缺少」。
4. 每一份被害人筆錄各自產出一組程序問句，不得共用。

**G2-R07：條陳格式生成**
1. 依所別與受理性質對應之模板產出（見 G2-R13）。模板固定文字不得改寫，只填入對應內容。
2. 案由欄：列出 Gate 2 之案類候選名稱，格式為「罪章（受理）」或「罪章（告發）」，依受理性質決定。多個候選時全部列出，並標示「候選」，不得自行選定。
3. 發生時間、發生地點、案情摘要依內容生成。
4. 報案時間、證明單案號、管轄單位、受理員警由受理人員自行填寫。
5. 證明單案號欄依 Gate 1 案號事實填寫；未記載者保留空白，加 warning。
6. 165 案號：罪章為詐欺時，於證明單案號後加「165 案號：」；非詐欺時省略。
7. 婦幼案號：被害人為代號或婦幼案件時顯示，案號由受理人員自行填寫。
8. 案情摘要須依 C-R17 精簡個資，並以客觀事實描述，不引用報告用語作為案類依據。
9. 轄區外受理者（G1-R17）不產出本所名義之條陳，改標示「建議移送」。

**G2-R08：既遂與未遂判斷**
每個案類候選須判斷既遂、未遂（行為已著手但未完成）或預備其他（依法不罰者註明）。不足以判斷者標 UNKNOWN，加 warning。

**G2-R09：告訴狀態**
1. 僅適用於受理性質為受理、告訴之紀錄。備案、告發不適用。
2. 告訴乃論之案類，若被害人表示不提告、不需協助、拒絕告訴或已撤回，標示「告訴未成立」，加 warning，強行通過。「不需警方協助」等同於不提告。
3. 告訴意思為「未定」者，標示「告訴意思未定」，加 warning，強行通過。
4. 警方依職權之通報（如家庭暴力通報）不改變告訴狀態。
5. 告訴未成立後若被害人之後提告，依 G1-R09 重新判斷告訴期間。
6. 非告訴乃論之案類，告訴狀態標 NOT_APPLICABLE。

**G2-R10：相關罪章檢核（限定清單）**
案類候選完成後，檢核下列範圍內是否有相關罪章可能成立：
1. 刑法內部：想像競合（第 55 條）、數罪併罰（第 50、51 條）。
2. 特別法：洗錢防制法、毒品危害防制條例、家庭暴力防治法、兒童及少年性剝削防制條例、個人資料保護法、詐欺犯罪危害防制條例。

檢核結果為「無」者註明「經檢核無相關罪章」；不足以判斷者標 UNKNOWN，加 warning。本規則只列候選，不作成立與否之判斷。清單以外之特別法由使用者另行判斷。

**G2-R11：雙重身份的被害人筆錄**
每位雙重身份者的被害人問句，只針對其為被害人的單元產出，依 G1-R06 每個被害單元一份。案類與告訴乃論各自獨立判斷。

**G2-R12：告訴期間判斷**
1. 依 G1-R09 之起算依據判斷告訴期間是否經過。
2. 期間已經過者，標示「已逾告訴期間」，加 warning，強行通過。
3. 期間未明或起算點 UNKNOWN 者，標 UNKNOWN，加 warning。
4. 不作正式期間計算結論，由使用者確認。

**G2-R13：所別與受理性質對應模板（修正）**
1. 依報告單位之抬頭判定所別（如「吳興所報告」「三張所報告」「信義分局報告」）。
2. 依受理性質判定文件類型（受理、告發、其他）。
3. 模板依「所別 × 文件類型」對應，每組模板另檔管理，固定文字不得改寫。
4. 所別或文件類型無法判定，或無對應模板者，不得套用其他模板，標 UNKNOWN，加 warning，由受理人員指定。
5. 信義分局報告與所報告格式不同時，以對應模板為準，不得混用。

**G2-R14：多被害人與多行為人**
1. 同一事件有多名被害人者，每名各自建立被害單元，各自產出被害人筆錄與程序問句。
2. 同一事件有多名行為人者，每名各自建立行為單元。
3. 共犯關係記錄於程序與其他要件事實之共犯欄，不得以共犯關係合併單元。

**G2-R15：追訴權承接**
1. 承接 Gate 1 之追訴權狀態，不得重新計算。
2. 追訴權已消滅者，標示「追訴權已消滅」，加 warning，強行通過。
3. 追訴權狀態為 UNKNOWN 者，加 warning，承接至 Gate 3。

### 7.5 受理條陳固定格式（吳興所受理模板範例，僅供說明）

```text
吳興所報告：
一、案由：
二、發生時間：
三、發生地點：
四丶報案時間：
五丶案情摘要：

(一)依規定受理(證明單案號：、婦幼案號：)
(二)管轄單位：
(三)受理員警：
```

其他所別或文件類型之模板依 G2-R13 另檔管理，不得套用本格式。

## 8. Gate 3：涉嫌人筆錄問句生成

### 8.1 目的
依 Gate 1 行為單元為主體，引用被害單元進行比對。路由 A 依 Gate 2 候選罪章與法條；路由 B 依 Gate 1 標示之罪章與法條。生成涉嫌人筆錄問句與涉嫌人程序問句。

### 8.2 核心設計
1. 涉嫌人看到的只有白話問句。
2. 法條、三階層、因果論、三段論只放內部對應表，不給涉嫌人看。
3. 問句以開放式為主，合併相關問題，節省紙張。
4. 每個問句對應至少一個罪章、一個三階層位置、一個要素。
5. 被害單元僅供比對與對質，不得將被害人主觀評價寫入涉嫌人問句。
6. 不判定刑責，不判定追訴權或告訴期間，只承接 Gate 1 與 Gate 2 之標示。
7. 每個行為單元各自一組問句與內部對應表，不得合併。

### 8.3 輸出結構

```text
涉嫌人筆錄問句：
  引用 unit_id：
  輔助比對引用 unit_id：
  引用罪章與法條來源：Gate 2 候選（路由 A）／Gate 1 標示（路由 B）

  一、基本資料與關係
  二、事件經過
  三、相關物品、內容或紀錄
  四、事後聯絡與態度
  五、其他特殊情形
  六、補充

涉嫌人身分狀態：RESOLVED／UNRESOLVED
告訴狀態標示：（依 G3-R13）
追訴權狀態標示：（依 G3-R13，承接 Gate 1）

涉嫌人程序問句：
  引用 unit_id：
  - 管轄問句：
  - 告訴期間問句：
  - 告訴乃論問句：
  - 程序要件問句：
  - 其他法律要件問句：

內部對應表（不給涉嫌人看）：
  題號 | 對應罪章 | 德日三階層 | 三段論 | 因果論 | 要素 | 刑法第23條對應（互毆時）

warnings（每筆含 source_gate）：
```

### 8.4 規則清單

**G3-R01：白話無法律術語**
問句不得出現法律術語，例如構成要件、該當、故意、意圖、散布、攝錄、妨害性隱私、性影像、猥褻、阻卻違法、責任能力。

**G3-R02：開放式非是非題**
問句以「請說明」「如何」「為何」「何時」「何地」「何人」等開放式問法為主，不以「是不是」「有沒有」「對不對」為主。

**G3-R03：不引導**
問句不得暗示答案。例如不問「你是不是未經同意拍攝？」，應問「請說明拍攝的完整經過」。

**G3-R04：節省紙張**
相關問題須合併，不得一個問題只問一個小點，不得每題留大片空白。

**G3-R05：對應罪章**
每個問句須對應至少一個罪章，不得產出無對應罪章之問句。路由 A 之罪章來自 Gate 2 候選；路由 B 之罪章來自 Gate 1 標示。

**G3-R06：對應三階層**
每個問句須對應德日三階層之一（構成要件該當性、違法性、有責性），三階層均須被涵蓋。

**G3-R07：對應因果論**
涉及行為與結果之問句，須對應因果論節點，節點須明確。

**G3-R08：對應人事時地物**
每個問句須對應至少一個要素（人、事、時、地、物），人事時地物均須被涵蓋。

**G3-R09：warning 繼承**
Gate 2 warnings（路由 A）或 Gate 1 warnings（路由 B）須完整傳入 Gate 3，保留原文，只能新增，並加 source_gate。

**G3-R10：涉嫌人程序問句**
1. 管轄、告訴期間、告訴乃論、程序要件、其他法律要件，每項至少一組。
2. 問句白話、開放式、不引導。
3. 引用 unit_id，繼承 warning。
4. 無缺少時寫「無」或「目前無缺少」。
5. 路由 B 之告訴乃論、告訴期間問句標示 NOT_APPLICABLE。

**G3-R11：禁止收集項目**
基本資料不得收集身分證字號、職業。問句中不得要求涉嫌人提供上述資料。

**G3-R12：涉嫌人身分未確認**
1. 以單元為單位判斷。只有涉嫌人身分 UNRESOLVED 的單元，不得產出涉嫌人白話問句。
2. 身分已確認的單元照常產出。
3. UNRESOLVED 單元輸出：「涉嫌人身分未確認，暫不產出涉嫌人問句」、待確認事項（身分、與事件之關係）、內部對應草稿。
4. 此狀態加 warning，並傳出最終輸出。

**G3-R13：告訴狀態與追訴權標示（修正）**
1. Gate 2 標示「告訴未成立」「告訴意思未定」或「追訴權已消滅」者，Gate 3 須於輸出開頭標示。
2. 路由 B 之追訴權狀態承接 Gate 1 標示，Gate 3 不得重新判斷。
3. 上述情形之涉嫌人問句仍依 G3-R01 至 G3-R11 生成，並加 warning，說明狀態不影響問句生成，最終是否追訴由使用者判斷。

**G3-R14：雙重身份與互毆**
1. 每位涉嫌人的每個行為單元各自產出一組白話問句與內部對應表，不得合併。
2. 對質比對只引用對方單元的 unit_id。
3. 互毆案件之內部對應表，於違法性層次加入刑法第 23 條對應欄。依實務見解，互毆須檢核「先行出手」及「反擊是否為必要排除現在不法侵害之行為」，此項為內部對應，不給涉嫌人看。

**G3-R15：共犯與多行為人**
1. 共犯之問句須包含共同行為之分工、與其他行為人之關係、聯絡方式與經過。
2. 每位行為人各自一組問句，不因共犯關係合併。
3. 內部對應表標示「共犯（刑法第 28 條至第 31 條，待查）」。

**G3-R16：未確定被害人之行為**
Gate 1 之未確定被害單元（G1-R10）所涉之行為，若行為人已確定，產出涉嫌人問句，被害人以「對方」或「店家」等中性描述，不得以推測身分代替。

**G3-R17：路由 B 之罪章待確認**
路由 B 之法條標示為 UNKNOWN 或法條狀態非「已確認」者，該問句標示「罪章待確認」，不得由 Gate 3 自行推定條次。

## 11. 法條擴充程序（新增）

法條擴充須依下列程序，不得跳過：

1. **範圍確認**：由使用者決定擴充之類別（如刑法分則章別、特別法類別）。
2. **原文取得**：依來源取得條文原文，記錄來源網址與查證日期。二手來源者，須補查原文後才能升為「已確認」。
3. **表格登錄**：依第 9 節格式登錄，最重本刑與追訴期間須由條文原文核對。
4. **告訴乃論核對**：依第 287 條所列及各罪章之明文規定核對，不得以報告用語判斷。
5. **狀態升級**：原文核對完成後，狀態升為「已確認」，並記錄版本。
6. **批次控管**：每批以不超過 20 條為原則，批次完成後更新版本，不得與架構修正同批進行。

第一批範圍建議：刑法第 135、277、284、309、320、335、336 條之 2、339、354、185 條之 3、319 條之 1 至之 6，共計約 15 條。

4. 備案中含刑事內容者，僅以 warning 提示，是否需要更強的提示方式。

6. C-R21 案號格式清單，需由受理單位提供。
7. 第一批法條範圍（第 11 節）是否如所列，或調整。
